# QuickTransfer 安全设计

本文描述当前安全边界和运行要求。安全能力必须以服务端真实状态为准，不能仅凭页面文案、进程存活或基础签名检查宣称可用。

## 1. 主要威胁

- 批量注册、撞库、验证码轰炸和自动化滥用；
- 超大任务、并发分片、恶意续传和磁盘耗尽；
- 恶意文件、可执行文件伪装和扫描器不可用；
- 分享链接、取件码、上传票据或下载票据被猜测、重放或越权使用；
- 领取次数并发争抢、重复扣费、提前删除或删除绕过；
- 管理员会话、SMTP、验证码、支付或存储共享密钥泄露；
- 代理头伪造、跨域上传、日志泄密和备份恢复错误；
- 支付回调伪造、兑换码重复消费和退款造成负余额。

## 2. 身份与会话

- 密码使用服务端强哈希保存，数据库不保存明文密码。
- 登录会话使用 HttpOnly Cookie；HTTPS 环境使用 Secure 与正确的 SameSite 策略。
- 状态修改接口要求 CSRF，改密后轮换会话与 CSRF，并撤销旧会话。
- 管理员长期凭据只允许存放在受访问控制保护的秘密存储中，不进入公开配置、源码、日志、页面或聊天。
- 管理员操作依赖角色、会话、CSRF、修订号、限流和审计；不额外要求密码或验证码确认。
- 用户状态停用后，现有会话必须失效或在下一次鉴权时被拒绝。

## 3. 注册、邮箱与人机验证

- 注册由管理员开关控制，默认关闭。
- 只接受 QQ、163 和 Gmail 精确域名，拒绝 `+` 别名，并对 Gmail 点号地址归一化。
- 发码对邮箱、来源 IP 和域名分别执行持久化频率限制；验证码只保存不可逆摘要并设置短有效期。
- 普通页面不回显验证码；SMTP 未完成真实投递测试时不得开放注册。
- Turnstile 或腾讯验证码只用于注册、登录、找回、游客传输、兑换、异常流量等反机器动作。
- 开启动作保护前必须同时具备完整客户端配置、服务端密钥、允许域名和服务端验签；缺少任一项时 readiness 或该动作失败关闭。
- 验证码通过不能替代密码、邮箱验证码、权限或流量检查。

## 4. 上传与内容安全

- 控制面只签发短时能力，文件字节直接进入存储面。
- 存储面校验任务、文件、偏移、分片大小、总量、来源和票据有效期。
- 上传先进入隔离区，完整后再扫描；只有扫描通过的对象才能原子发布。
- 高风险扩展名、签名不匹配和已知测试恶意内容必须被阻断。
- 生产存储必须使用 `QT_STORAGE_SCAN_MODE=required`。扫描引擎不可用、超时或返回不确定结果时 readiness 失败，文件不能发布。
- 本地 `signature` 模式只能用于开发与受控验收，必须报告 `productionScanner=false`。
- 磁盘余量、全局并发、来源 IP 并发、读取空闲超时和最大持续时间都由存储面执行。

## 5. 控制面与存储面信任

- 两个服务使用独立 SQLite、独立数据目录和最小权限账户。
- 回调和内部请求使用 HMAC、时间戳与短重放窗口；共享密钥只从 ACL 保护文件读取。
- 浏览器上传与下载能力必须短时、限定动作、任务和对象，不能作为长期身份凭据。
- CORS 只允许明确配置的可信来源，不使用通配符。
- 只有明确配置的代理网段可以提供真实来源地址；不信任任意客户端提交的转发头。
- 控制面不代理 `/storage/v1/uploads` 或下载主体，避免带宽、检查和故障边界重新耦合。

## 6. 领取次数状态机

- 新会话名额在数据库事务中原子领取，最后一个名额不能被两个请求同时取得。
- 同一会话可以领取全部文件，不按文件数重复计次。
- 30 分钟后停止签发新票据；已经开始的流在 48 小时硬截止内结算。
- 只有从未开始下载的临时票据可以归还名额。
- 次数耗尽后，链接、取件码和票据接口共同拒绝新会话，不能只依赖前端禁用。
- 自动删除前必须确认没有活动或正在结算的会话；删除失败保持可重试，不伪造成功状态。
- 存储面删除时阻断新读取，并等待已经开始的合法读取结束。
- 旧发送任务与收集任务通过显式兼容字段隔离，不获得追溯删除行为。

## 7. 流量、订单与兑换

- 上传流量使用预留、结算、释放三态事务；完成回调幂等，不能重复扣费。
- 下载协议不携带用户流量计费字段，下载回调不能改变上传余额。
- 现金订单必须校验提供方、订单号、金额、币种、签名和回调幂等；未实现时保持不可用。
- 积分兑换和现金购买是独立路径，不能互相伪造完成状态。
- 兑换码使用摘要完成匹配，使用应用密钥经 AES-GCM 加密保存可恢复内容；完整码只向已认证管理员返回，普通接口、日志和审计不得泄露。
- 每个兑换码只能原子消费一次；唯一约束和事务保证并发兑换只有一个成功者，并记录兑换用户与时间。
- VIP 退款在没有可撤销权益账本前失败关闭，不能直接减余额或删除权益。
- 会员每日登录赠送以 `(user_id, Beijing date)` 唯一约束防重；实时校验会员是否有效，不信任浏览器传入的等级、日期或金额。
- 会话、`last_login_at`、会员日赠记录、永久流量权益和审计必须同事务提交；任一写入失败都回滚登录，不允许出现已登录但未到账或到账却没有会话的半状态。
- 月卡、年卡、终身卡每日金额分别固定为 200 MiB、500 MiB、1 GiB；该自动权益与主动签到使用不同来源账本，互不覆盖。

## 8. 日志、秘密与备份

- 日志不得记录密码、Cookie、CSRF、验证码、SMTP 授权码、支付密钥、共享密钥或完整兑换码。
- 配置秘密使用操作系统提供的凭据保护能力或最小权限文件存储。
- 数据库备份使用 SQLite 一致性方式并执行 `PRAGMA quick_check`；不能在服务运行时只复制主数据库而忽略 WAL 边界。
- 控制库和存储库分别恢复；二进制回滚不自动覆盖已经迁移的数据库。
- 删除旧备份前至少保留当前数据版本的一份已验证恢复包。

## 9. 运行防护

- 控制面和存储面均以最小权限运行，并限制不必要的网络暴露。
- 对外入口使用受信任 TLS、精确访问控制和独立的数据边界。
- readiness 必须包含数据库、存储、扫描器和关键配置状态；存活不等于可接收上传。
- 异常流量触发速率限制、人机验证、临时拒绝或运维告警，不能通过提高账号额度绕过。

## 10. 安全事件处理

1. 立即关闭注册、支付或受影响动作；
2. 保留日志、审计、数据库和配置快照，不直接手改 SQLite；
3. 轮换受影响的管理员、SMTP、验证码、支付或存储共享密钥；
4. 撤销相关会话、能力票据和兑换批次；
5. 核对用户余额、订单、对象、outbox 和任务状态；
6. 修复后完成真实端到端闭环，再恢复功能；
7. 记录影响范围和恢复证据，但不在记录中复制秘密值。
